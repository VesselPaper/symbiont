# 演示手册

这份是上台时拿在手里的操作单。所有命令都已经在本机跑过一遍，下面的"屏幕上会出现什么"是实测输出，不是预期。

## 一、演示要证明的三件事

第一，没有网关的时候，链路是明文，源站谁都能打，接口文档直接敞着。

第二，加上网关之后，这些口子被堵上，而且不是靠"配了就算"，每条都能在现场看见。

第三，三台后端真的在轮流接活，停掉一台服务不中断，代价是那个五秒。

演示不是走配置，是把这三句话各自变成一个看得见的画面。

## 二、上台前 20 分钟的准备

按顺序做，每一步都有个可以对照的结果。

```powershell
# 1 生成自签证书，只做一次。证书在 deploy/certs/，已经有就不用重跑
scripts/gen_cert.ps1

# 2 导出 Web 包。网关会把 client/build/web 挂进容器，没有包就只有落地页
scripts/export_web.ps1

# 3 起网关栈，带三副本
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.scale.yml up -d

# 4 起对照栈，裸奔那一套，端口 18081 和 13307
docker compose -f deploy/ops/docker-compose.before.yml up -d
```

对照结果：

```powershell
docker ps --format "{{.Names}}\t{{.Status}}"
```

应该看到六个都 healthy：`symbiont-proxy-1`、`symbiont-server-1`、`symbiont-server-2-1`、`symbiont-server-3-1`、`symbiont-mysql-1`，再加对照栈的 `symbiont-baseline-server-1` 和 `symbiont-baseline-mysql-1`。

起完先自己访问一次 `https://localhost/api/v1/health`，确认返回里 `instance` 是 `node-1`。

浏览器第一次打开 `https://localhost` 会报证书不安全。走之前把根证书装上，演示时就不会弹：

```powershell
scripts/trust_ca.ps1
```

## 三、第一幕：从没有网关到有网关

### 第 1 步　直接打后端

```powershell
curl.exe -si http://localhost:18081/api/v1/health
```

屏幕上会看到三样东西。协议是 `HTTP/1.1` 而不是 https，整条链路谁都能读。响应头只有 date、content-length、content-type，没有任何安全头。返回体里的 `instance` 是空的，因为只有一台。

再说一句：接口文档也敞着。

```powershell
curl.exe -si http://localhost:18081/docs
```

返回 `HTTP/1.1 200 OK`。

### 第 2 步　链路上挂一个中继

中继要单独开一个终端，占着不关。

```powershell
python deploy/ops/tap.py --listen 18100 --target 18081
```

然后另一个终端发请求：

```powershell
curl.exe -s http://localhost:18100/api/v1/health
```

中继那个窗口会打印出完整的一行 `GET /api/v1/health HTTP/1.1`，下面接着是请求头和整个 JSON 正文。这就是链路上任何一个人能看到的东西。

### 第 3 步　同一段链路换成 443

```powershell
python deploy/ops/tap.py --listen 1443 --target 443
curl.exe -sk https://localhost:1443/api/v1/health
```

中继这次打印的是二进制，前 64 字节是 `16 03 01 01 ba ...`。同一段链路，内容看不见了。

### 第 4 步　源站还在不在外面

```powershell
docker port symbiont-server-1
docker port symbiont-mysql-1
```

两条命令都没有输出。这一步比任何配置都关键，源站只要还能被直连，前面所有策略都可以绕过。

顺便让网关自己回答一次：

```powershell
curl.exe -skI https://localhost/api/v1/health
```

会看到 `Server: nginx` 但没有版本号，`X-Upstream` 是这台请求实际落到哪台后端，下面跟着 `X-Content-Type-Options`、`X-Frame-Options` 这两个安全头。

### 第 5 步　九十六兆过网关

先看内存，再传，再看内存。三条命令分三次敲，中间留几秒。

```powershell
docker stats --no-stream --format "{{.Name}}  {{.MemUsage}}" symbiont-proxy-1
curl.exe -sk -o NUL https://localhost/game/index.pck
docker stats --no-stream --format "{{.Name}}  {{.MemUsage}}" symbiont-proxy-1
```

本机实测是 35.13MiB 到 35.93MiB。六十多兆的东西过去了，网关内存没动。说的那句是：如果它先把整个响应缓冲下来，内存曲线会跟着包体走。

## 四、第二幕：负载均衡

### 第 6 步　分流

```powershell
python deploy/ops/bench.py --mode seq --n 12
```

输出里三行：node-1 四次，node-2 四次，node-3 四次，成功率一百。

要说的是"看分布不看可用性"，服务可用是默认，分布才说明配置生效。

### 第 7 步　限流

```powershell
python deploy/ops/bench.py --n 40 --concurrency 40
```

实测二十一个 200，十九个 429，成功率五十二。三台各七次。

这里主动解释二十一这个数：配置是每秒八个加突发二十，一瞬间最多放过二十一个，其余直接拒。为什么是 429 不是 503，下一页或者上一页里有。

### 第 8 步　停一台

```powershell
docker stop symbiont-server-2-1
python deploy/ops/bench.py --mode seq --n 9
```

实测九次全成功，落在 node-1 和 node-3，但最慢一次 5007 毫秒。

这句必须说：成功率一百，可是有一个请求要等五秒。那个请求正好打在已经死掉的实例上，要等连接超时到点才重试下一台。被动健康检查的代价就在这里。

### 第 9 步　放回来

```powershell
docker start symbiont-server-2-1
```

等十秒左右再跑一次：

```powershell
python deploy/ops/bench.py --mode seq --n 12
```

三台又均匀了。

## 五、三个预案

**Docker 起不来或者容器飘红。** 别在台上等。提前把九条命令各跑一遍，用手机或录屏把终端画面拍下来，出问题就投图讲，说一句"这台机器刚才还是好的，我们直接看录制"，然后往下走。PPT 第 14 页有全部数字，缺一步也能讲完。

**端口被占。** 80/443/18081/13307 这几个在本机是空的，但演示机器如果是别人的，先 `Get-NetTCPConnection -LocalPort 80` 查一下。被占就改对照栈端口，别改网关端口，因为证书是按 localhost 签的。

**浏览器说证书不安全。** 装根证书 `scripts/trust_ca.ps1`。来不及就用 curl 演示，不打开浏览器，效果是一样的，甚至更干净。

## 六、讲完收尾

```powershell
docker compose -f deploy/ops/docker-compose.before.yml down
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.scale.yml down
```

数据卷不删，下次起来不用重新初始化数据库。要连数据一起清就加 `-v`，但那样会丢掉 mysql 里的账号和存档。
