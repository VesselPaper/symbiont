# 演示手册

主戏只有两样：**我们自己的项目在浏览器里真的跑起来**，以及**我们自己的代码**。那个落地页和状态页是之前顺手做的辅助页，用来指一下三台后端在不在，不承担主要讲解。

所有命令都在本机跑过，下面的输出是实测，不是预期。

## 一、三层材料

| 层 | 用什么 | 说明 |
|---|---|---|
| 主 | 浏览器打开 `https://localhost/game/`，真的玩 | 这一层证明"Web 访问"不是假设，游戏是通过我们自己的网关加载的 |
| 主 | 终端里跑 curl、中继、bench、docker port、docker stats | 这一层证明网关每条职责都真的生效 |
| 主 | 代码截屏，四五张 | 这一层证明配置是我们自己写的，不是套模板 |
| 辅 | `https://localhost/status.html` | 顺手做的状态页，只看一眼三台分布，别当主戏 |

## 二、上台前 20 分钟

```powershell
scripts/gen_cert.ps1
scripts/export_web.ps1
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.scale.yml up -d
docker compose -f deploy/ops/docker-compose.before.yml up -d
docker ps --format "{{.Names}}\t{{.Status}}"
```

七个容器都 healthy 才算好。然后用浏览器打开一次 `https://localhost/game/`，等到游戏画面出来再关掉。这一步是**预热缓存**：首屏要过九十六兆，第一次打开慢，缓存热了之后第二次打开是秒开，演示时不能让人等。

浏览器第一次会报证书不安全，装一次根证书就不弹了：`scripts/trust_ca.ps1`。

## 三、第一幕：真的跑起来

### 1. 打开游戏

```
https://localhost/game/
```

游戏出来之后操作两下，让人看见角色会走、会跳、会砍。

要说的是：这个页面不是静态截图，是 Godot 导出的 Web 版，`index.pck` 五十八兆、`index.wasm` 三十八兆，全部从这台机器的网关加载。浏览器地址栏里的域名就是我们自己签的证书。

顺带说一个细节，这个细节能证明我们真跑过：导出时关掉了多线程，所以不需要给浏览器发 COOP 和 COEP 这两个跨域隔离头，少了一层部署麻烦。

### 2. 看一眼网关状态页

```
https://localhost/status.html
```

这页只做一件事：显示后端实例分布。用它引出"为什么三台、它们怎么被调度"就够了，后面的证据都在终端里。

## 四、第二幕：没有网关和有网关

### 3. 直接打后端

```powershell
curl.exe -si http://localhost:18081/api/v1/health
curl.exe -si http://localhost:18081/docs
```

第一行是 http，整条链路谁都能读；响应头里没有任何安全头；返回体里的 `instance` 是空的，因为只有一台。第二行说明接口文档也敞着，返回 200。

### 4. 中继看明文

一个终端占着：

```powershell
python deploy/ops/tap.py --listen 18100 --target 18081
```

另一个终端发请求：

```powershell
curl.exe -s http://localhost:18100/api/v1/health
```

中继窗口打印出完整的一行 `GET /api/v1/health HTTP/1.1`，请求头和整个 JSON 正文都在。

### 5. 中继看密文

```powershell
python deploy/ops/tap.py --listen 1443 --target 443
curl.exe -sk https://localhost:1443/api/v1/health
```

只剩 `16 03 01 01 ba ...` 一串十六进制。

### 6. 源站还在不在外面

```powershell
docker port symbiont-server-1
docker port symbiont-mysql-1
```

两条都没有输出。这一步比任何配置都关键，源站只要还能被直连，前面所有策略都能被绕过。

```powershell
curl.exe -skI https://localhost/api/v1/health
```

`Server: nginx` 不带版本，`X-Upstream` 显示这次落在哪台，下面跟着三个安全头。

### 7. 九十六兆过网关

```powershell
docker stats --no-stream --format "{{.Name}}  {{.MemUsage}}" symbiont-proxy-1
curl.exe -sk -o NUL https://localhost/game/index.pck
docker stats --no-stream --format "{{.Name}}  {{.MemUsage}}" symbiont-proxy-1
```

本机实测 35.13MiB 到 35.93MiB。六十多兆过去，内存没动，说明是边收边转，没有整块缓冲。

## 五、第三幕：三台在干活

### 8. 分流

```powershell
python deploy/ops/bench.py --mode seq --n 12
```

node-1、node-2、node-3 各四次，成功率一百。

说的是：看分布不看可用性，服务可用是默认，分布才说明配置生效。

### 9. 限流

```powershell
python deploy/ops/bench.py --n 40 --concurrency 40
```

二十一个 200，十九个 429，三台各七次。

主动解释二十一：每秒八个加突发二十，一瞬间最多放过二十一个。

### 10. 停一台

```powershell
docker stop symbiont-server-2-1
python deploy/ops/bench.py --mode seq --n 9
```

九次全成功，落在 node-1 和 node-3，最慢一次 5007 毫秒。这句必须自己说出来：成功率一百，但有一下要等五秒，因为那个请求打在已死实例上，要等连接超时到点才换台。

### 11. 放回来

```powershell
docker start symbiont-server-2-1
```

等十秒，再跑 `--n 12`，又均匀了。

## 六、代码截屏清单

截四到五张，用编辑器自己的深色主题就行，不要加工。每张只留十几行，别整屏截。

| 截什么 | 位置 | 配的话 |
|---|---|---|
| 限流的 zone 与状态码 | `deploy/nginx/templates/default.conf.template` 第 9 到 17 行 | 429 不是随手写的，默认 503 会把责任推给后端 |
| 安全头那一段 | 同文件第 56 到 65 行 | 这几个头对所有响应生效，注意 nginx 的覆盖规则 |
| `/api/` 反代那一段 | 同文件第 97 到 118 行 | 转发头是信任链的起点，超时是分层的 |
| 地址池 | `deploy/nginx/templates/upstream.conf.template` 全文 | zone 不能省，keepalive 加了还要配 http 版本 |
| expose 而不是 ports | `deploy/docker-compose.yml` 第 30 到 33 行与第 55 到 58 行 | 改动最大的是这一行，源站不出内网 |

## 七、预案

Docker 飘红：别在台上修。提前把上面每条命令的输出拍成照片或录屏，出问题投图讲，说一句"这台机器刚才还是好的，看录制"，继续往下。

浏览器打不开或者卡：先排除缓存和证书，再退到 curl 演示，效果一样。游戏这一层实在起不来，就把第一幕换成提前录好的一段 30 秒操作视频，重点转到终端数据。

端口被占：只改对照栈的 18081 和 13307，网关的 80 和 443 不要动，证书是按 localhost 签的。

## 八、收尾

```powershell
docker compose -f deploy/ops/docker-compose.before.yml down
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.scale.yml down
```

不加 `-v`，数据卷留着，下次起来不用重新初始化数据库。
