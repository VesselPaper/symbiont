浏览器自动携带身份 不成立 后端没有 cookie 与会话，跨站请求不携带任何身份。
攻击者可构造请求 成立 表单可正常发出，响应中的 400 与 405 表明请求已到达服务器。
服务端仅校验请求本身 成立 接口信任 X-Device-Id，且不校验该 id 的归属；风险转移至应用层无认证。

结论

经典 CSRF 在该接口上不成立。后端没有身份概念：没有 cookie、没有会话、没有令牌，浏览器不会在跨站请求中自动携带任何身份。实际风险位于应用层：接口仅信任请求头中的设备 id，而该 id 可自行编造。

curl.exe -k -s "https://localhost/api/v1/saves/0"
curl.exe -k -s -X POST https://localhost/api/v1/saves/0 -d "save_data=x"
curl.exe -k -s https://localhost/api/v1/saves/0 -H "X-Device-Id: attack-probe-0001"
