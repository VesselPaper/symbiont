# 00 项目计划与流程

课程：软件工程（2024 级）｜组号：2 组｜项目：共生之缚 Symbiont（自主选题，类恶魔城 2D 游戏）。
范围：**方案 B** —— 游戏客户端（Godot 4.5）+ 轻量后端（FastAPI+MySQL）+ docker 全栈（详见下文"范围决策"）。

## 1. 目标与成功标准

1. 游戏可玩：三层地牢、双流派（献祭流 / 探索流）、三结局（人类/异化/真 HE）、存档可用、无致命 bug；
2. 后端：FastAPI + MySQL，REST API 有 OpenAPI 文档、pytest 全绿、数据真实入库；
3. `docker compose -f deploy/docker-compose.yml up -d` 一键拉起 MySQL+后端+游戏 Web 版，浏览器可玩；
4. 课程 7 份文档（docs/01–07）+ 数据库脚本（database/）+ 每周实施周报（docs/weekly/）齐备；
5. 代码质量：CI 绿、main 保护、PR review、README 完整。

## 3. 范围决策（B 为默认；A/C 影响）

- **A（最小）**：只游戏 + SQLite 管道 + Web nginx 镜像。技术面偏薄，不推荐。
- **B（本计划采用）**：A + FastAPI+MySQL 后端（账号/远程存档/统计埋点/排行榜）+ docker-compose 全栈。
- **C（stretch）**：B + Web 管理看板（webadmin/），核心完成且有余力再做。
- 后端与客户端解耦（网络层离线优先），M0 后再改 A/B 不影响游戏开发。

## 4. 技术栈（锁定）

Godot 4.5.1（纯 GDScript）｜GUT/无头冒烟测试｜JSON 数据管道（SQLite→JSON）｜存档 JSON v1｜FastAPI+SQLAlchemy+MySQL 8+pytest｜docker-compose（mysql8+server+nginx）｜GitHub Actions CI｜Kenney CC0 素材 + AI 像素画。

## 6. 团队分工（6 人，可兼任）

- 架构与集成（主力·技术支持）：总体架构、Godot 骨架、客户端↔服务器接口、审核合并、CI
- 游戏设计（主力·游戏想法）：GDD、剧情/数值/关卡、手感验收、决策清单拍板
- 客户端开发 ×2：场景/敌人/道具/UI，与 agent 结对
- 后端开发 ×1：FastAPI+MySQL+docker，与 agent 结对
- 美术与资产 ×1：Kenney 整理、AI 像素画、音频、整合
- 测试与文档 ×1：GUT/pytest、课程 7 文档、周报、操作手册

## 7. 协作硬规则

1. `main` 保护，禁直接 push；每任务一个 `feature/xx` 分支 → PR → ≥1 人 review → CI 绿合并；
2. 设计文档先行：agent 只实现任务卡内容，不发明功能、不改接口、不调数值；
3. 手感/剧情决策永远是人（agent 无法替代）；
4. 数值全部参数化（进 database/balance 或 JSON），代码不写死；
5. 每周日提交实施周报（docs/weekly/，命名：组2-共生之缚-实施周报-yyyymmdd）；
6. 文档与代码注释用中文。

## 8. Agent 工作方式（吸取上次教训）

上次失败根因：一次性让 agent 做"整个游戏"、无验收、手感美术失控。本次：

- **任务卡制**：每任务一张卡（docs/tasks/），含输入（设计文档章节）、实现要求、验收标准、禁止事项、产出；
- **小步验收**：每个 agent 任务独立分支 + 可运行检查点，CI 兜底；
- **人机分工**：agent 写代码与测试；人做设计、审核、试玩、手感调优；
- **上下文交接**：docs/design + docs/tasks 是 agent 的"记忆"，开工先读相关章节。

任务卡模板见 `docs/tasks/TASK_TEMPLATE.md`，M0 任务卡见 `docs/tasks/M0-*.md`。
