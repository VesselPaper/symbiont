# M1-15 攀升竖井（垂直攀升 · 程序化地形）

- 编号：`M1-15`
- 标题：固定镜头垂直攀升模块 —— 地形持续下落 + 程序化平台 + 坚持 30 秒
- 指派：`agent:opencode` / 验收：`人:组长`

## 输入（前置依赖）

- 设计：`docs/design/GDD.md`（自下而上探索 / 双流派机动）
- 玩家手感：`client/scripts/player/player.gd`（重力 2550、跳跃初速 727 → 最大跳高 ≈ 103.6px）
- 复用：`client/scenes/player/player.tscn`（CharacterBody2D，collision_layer=2 / mask=1）
- 相机口径：`client/scripts/world/test_arena.gd`（zoom = 720 ÷ (15×28) ≈ 1.714 → 可视约 747×420）

## 玩法规则（验收口径）

1. 相机固定一屏，不跟随；左右有墙，玩家只能在竖井内活动。
2. 地形（平台）整体匀速下落，玩家站在平台上会被一起带下去。
3. 平台从屏幕下沿移出后回收到顶部，按"必然可达"规则重新摆放。
4. 下落速度从"10 秒穿过全屏"线性加快到"5 秒穿过全屏"，爬升时长 = 生存目标 30 秒。
5. 玩家碰到屏幕最下沿的判定区 → **本模块重开**（地形重置、玩家回起点、计时归零）。
6. 坚持满 30 秒 → 通关（`module_completed` 信号）。

范围外一律不动（尤其不改 `player.gd` 数值与接口）。

## 实现要求

1. 平台用 `AnimatableBody2D` + `sync_to_physics = true`（否则不会载人，玩法不成立）。
2. 生成规则必须保证可达：垂直间距 ∈ [48, 80]（≤ 安全跳高 80 < 103.6），相邻水平偏移 ≤ 128px，平台宽 96px。
3. 速度曲线：`fall_speed = 可视高度 ÷ lerp(10, 5, progress)`。
4. 重开时在物理回调内用 `call_deferred` 重建平台（规范第 7 条）。
5. 数值全部放脚本顶部常量（对齐 M1 风格，M2 再迁入 `database/game_data`）。
6. 脚本**不引用 EventBus 全局**，只用本地信号（保证 `--script` 无头测试可加载）。
