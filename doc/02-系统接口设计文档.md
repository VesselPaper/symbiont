## 1. 概述与约定

### 1.1 接口定位
本文档定义客户端（Godot WebGL）、管理后台（Vue3）与 FastAPI 后端之间的全部 HTTP 接口，以及可选 WebSocket 接口。

### 1.2 Base URL 与版本
- 开发环境：`http://localhost:8000/api/v1`
- 生产环境：由 Docker Compose 暴露（`http://<host>:8000/api/v1`），客户端经 Nginx 反代同源访问 `/api`

### 1.3 认证方式
- 除注册 / 登录 / 刷新 / 公告 / 排行榜（只读）外，接口需在请求头携带：
  ```
  Authorization: Bearer <access_token>
  ```
- access token 有效期 60 分钟；过期后客户端用 refresh token 调用刷新接口获取新 access token；refresh token 有效期 7 天。

### 1.4 统一响应格式
所有接口返回：
```json
{ "code": 0, "message": "ok", "data": { } }
```
- `code = 0` 成功；非 0 为业务错误码（见 1.6）。
- HTTP 状态码：2xx 成功；4xx 客户端错误；5xx 服务端错误。

### 1.5 分页约定
分页参数统一为 `page`（从 1 起）、`page_size`（默认 20，最大 100）。分页响应 data 结构：
```json
{ "items": [], "total": 123, "page": 1, "page_size": 20 }
```

### 1.6 错误码表
| code | HTTP | 说明 |
|---|---|---|
| 0 | 200 | 成功 |
| 40000 | 400 | 请求参数错误 |
| 40001 | 401 | 用户名或密码错误 |
| 40002 | 409 | 用户名已存在 |
| 40100 | 401 | 未携带令牌 |
| 40101 | 401 | 令牌过期 |
| 40102 | 401 | 令牌无效 / 已被吊销 |
| 40301 | 403 | 无权限（非管理员） |
| 40401 | 404 | 资源不存在 |
| 40901 | 409 | 存档版本冲突（data 返回服务端最新版） |
| 42201 | 422 | 数据校验失败（含存档校验和不符） |
| 42901 | 429 | 触发限流 |
| 50000 | 500 | 服务器内部错误 |

### 1.7 时间与数值格式
- 时间：ISO 8601 字符串（`2026-03-01T12:00:00Z`），统一 UTC。
- 数值：通关时间 / 死亡数为数字；完成度为 0-100 的数值；星级为 0-3 整数。

## 3. 认证接口

### 3.1 POST /auth/register 注册
请求：
```json
{ "username": "player01", "password": "pass1234", "nickname": "玩家一号" }
```
- 校验：用户名 3-32 位（字母数字下划线）；密码 ≥ 8 位；昵称 ≤ 32 字符。

响应（成功）：
```json
{
  "code": 0, "message": "ok",
  "data": {
    "access_token": "eyJ...", "token_type": "bearer", "expires_in": 3600,
    "refresh_token": "eyJ...",
    "user": { "id": 1, "username": "player01", "nickname": "玩家一号", "role": "player" }
  }
}
```
错误：`40002` 用户名已存在；`42201` 校验失败。

### 3.2 POST /auth/login 登录
请求：`{ "username": "player01", "password": "pass1234" }`
响应：同注册成功结构。
错误：`40001` 凭据错误；`40301` 账号被禁用（status=banned）。

### 3.3 POST /auth/refresh 刷新
请求：`{ "refresh_token": "eyJ..." }`
响应：`data: { "access_token": "...", "expires_in": 3600 }`
错误：`40102` refresh 无效 / 过期 / 已吊销。

### 3.4 POST /auth/logout 登出
请求头携带 access token；服务端吊销该用户的 refresh token。
响应：`data: null`。

## 4. 云存档接口

### 4.1 GET /saves 存档列表
响应 data：
```json
{
  "saves": [
    { "slot": 1, "version": 3, "checksum": "a3f2...", "updated_at": "2026-03-01T12:00:00Z",
      "summary": { "level": "dungeon_entrance", "humanity": 62, "alienation": 38, "progress": 45.0 } }
  ]
}
```
（`summary` 由服务端从存档 JSON 提取用于列表展示，不含完整数据。）

### 4.2 PUT /saves/{slot} 上传播档（slot ∈ 1..3）
请求：
```json
{
  "version": 2,
  "data_json": { "level": "dungeon_entrance", "player": { "hp": 5, "max_hp": 6, "x": 120, "y": 80 },
                 "abilities": ["double_jump"], "items": ["vial_blood"],
                 "humanity": 62, "alienation": 38,
                 "explored": ["room_1", "room_2"], "timestamp": "2026-03-01T12:00:00Z" }
}
```
- 服务端行为：计算 data_json 的 SHA-256 存入 checksum；若请求 version < 服务端 version 且时间戳早于服务端 → 返回 `40901`，data 携带服务端最新存档，由客户端选择覆盖 / 保留。
- 强制覆盖：客户端可在请求头加 `X-Force-Overwrite: true` 跳过冲突检查。
- 成功响应：`data: { "slot": 1, "version": 3, "checksum": "...", "updated_at": "..." }`

### 4.3 GET /saves/{slot} 下载存档
响应 data：
```json
{ "slot": 1, "version": 3, "checksum": "a3f2...", "data_json": { "...": "..." }, "updated_at": "..." }
```
错误：`40401` 该槽位无存档；`42201` 校验和不符（数据异常）。

## 5. 排行榜接口

### 5.1 GET /leaderboard 排行榜分页
查询参数：
| 参数 | 说明 |
|---|---|
| metric_type | 必填：`clear_time` / `deaths` / `completion` |
| level_id | 可选；缺省为总榜 |
| page / page_size | 分页，默认 1 / 20 |

响应 data：
```json
{
  "items": [
    { "rank": 1, "user_id": 5, "nickname": "深渊旅人", "value": 128.5,
      "stars": 0, "achieved_at": "2026-03-01T12:00:00Z" }
  ],
  "total": 88, "page": 1, "page_size": 20,
  "my_rank": { "rank": 12, "value": 240.0 }   // 登录后返回；未登录为 null
}
```
- 排序规则：`clear_time` / `deaths` 升序（越小越好）；`completion` 降序。
- 数据源：热榜 Redis ZSET 缓存，未命中回源 MySQL。

### 5.2 GET /leaderboard/rank 个人名次
参数：`metric_type`、`level_id`（可选）。
响应 data：`{ "rank": 12, "value": 240.0, "total": 88 }`；无记录时 rank 为 null。

### 5.3 POST /leaderboard/submit 成绩上报
请求：
```json
{ "metric_type": "clear_time", "level_id": 2, "value": 128.5, "stars": 3 }
```
- 服务端校验：value 合法性（clear_time/deaths > 0；completion 0-100；stars 0-3）；该玩家该维度该关卡仅保留**最优成绩**（优于旧值才更新）。
- 响应：`data: { "improved": true, "rank": 6, "best": 128.5 }`
- 同时写入 `player_events`（event_type=parkour_result）供统计。

## 6. 统计接口

### 6.1 POST /stats/events 批量事件埋点
请求：
```json
{
  "events": [
    { "event_type": "session", "payload": { "duration": 120 } },
    { "event_type": "level_clear", "payload": { "level_id": 2, "time": 128.5, "deaths": 3 } },
    { "event_type": "death", "payload": { "level_id": 2, "pos": [120, 80] } },
    { "event_type": "ability_get", "payload": { "ability": "double_jump" } },
    { "event_type": "item_choice", "payload": { "item": "symbiont_core", "choice": "devour" } }
  ]
}
```
- 单次最多 50 条；服务端异步写入 `player_events`。
- 响应：`data: { "accepted": 5 }`

## 8. 管理后台接口（全部需 admin 角色）

### 8.1 关卡配置
**GET /admin/levels**（分页，可按 type / difficulty / ai_generated 过滤）
响应 data 条目标：
```json
{ "id": 1, "level_key": "dungeon_entrance", "name": "烬渊入口", "type": "main",
  "difficulty": "easy", "ai_generated": false, "enabled": true, "version": 1,
  "updated_at": "..." }
```

**POST /admin/levels** 新建
请求：
```json
{ "level_key": "dungeon_02", "name": "烬渊中层", "type": "main", "difficulty": "normal",
  "data_json": { "rooms": [], "player_start": { "x": 0, "y": 0 }, "theme": "dungeon" } }
```
- 校验：level_key 唯一、data_json 通过关卡 schema 校验。
- 响应：创建后的完整关卡对象。

**PUT /admin/levels/{id}** 更新（同上结构，version 自动 +1）
**DELETE /admin/levels/{id}** 删除（有关联排行数据时软删，置 enabled=0 更佳）
**PATCH /admin/levels/{id}/toggle** 启停：`{ "enabled": false }`

### 8.2 玩家管理
**GET /admin/players**（分页 + 关键字 / 状态过滤）
条目标：`{ "id": 1, "username": "player01", "nickname": "玩家一号", "role": "player", "status": "active", "total_play_seconds": 3600, "total_deaths": 42, "last_login_at": "..." }`

**PATCH /admin/players/{id}** 封禁 / 解封：`{ "status": "banned" }`
（操作写入 admin_logs。）

### 8.3 公告管理
**GET /admin/announcements**、**POST /admin/announcements**（title/content/enabled）、**PUT /admin/announcements/{id}**、**DELETE /admin/announcements/{id}**

### 8.4 数据看板
**GET /admin/dashboard/summary**
响应 data（ECharts 数据源）：
```json
{
  "daily_active": [ { "date": "2026-03-01", "players": 42, "sessions": 87 } ],
  "level_clear_rate": [ { "level_id": 1, "name": "烬渊入口", "attempts": 120, "clears": 88, "rate": 73.3 } ],
  "difficulty_distribution": [ { "difficulty": "easy", "players": 60 }, { "difficulty": "normal", "players": 25 } ],
  "play_time_distribution": [ { "bucket": "0-10min", "count": 30 } ],
  "item_choice_distribution": [ { "choice": "devour", "count": 40 }, { "choice": "offer", "count": 35 } ],
  "totals": { "players": 88, "total_sessions": 1560, "total_deaths": 421, "avg_clear_time": 150.2 }
}
```

### 8.5 管理日志
**GET /admin/logs**（分页）：`{ "id": 1, "admin_id": 2, "action": "level.update", "detail": "更新关卡 dungeon_02", "created_at": "..." }`

## 9. AI 接口（P2 可选）

### 9.1 POST /ai/levelgen AI 生成关卡
请求：
```json
{ "prompt": "一段需要二段跳和冲刺才能通过的中等难度房间", "difficulty": "normal",
  "room_size": { "w": 40, "h": 16 } }
```
- 服务端：调用 LLM → 关卡 JSON → schema 校验（失败自动重试 2 次）→ 返回。
响应：`data: { "level_key": "ai_gen_20260301_001", "name": "AI 生成关卡", "data_json": { "...": "..." } }`
- 入库由管理员在管理端确认后调用 POST /admin/levels 完成。
错误：`50000` LLM 连续失败；`42201` 生成结果不合法。

### 9.2 POST /ai/hint 卡关提示
请求：`{ "level_key": "dungeon_entrance", "position": [120, 80], "progress": { "abilities": ["double_jump"] } }`
响应：`data: { "hint": "试试向上看——高处的裂缝需要冲刺撞开。" }`（渐进：提示 → 思路 → 步骤，同关卡多次请求逐级深入）

## 10. 数据结构定义（DTO 汇总）

| 名称 | 字段 | 说明 |
|---|---|---|
| User | id, username, nickname, role, status, created_at | 账号（不返回 password_hash） |
| SaveMeta | slot, version, checksum, updated_at, summary | 存档元信息 |
| SaveFull | slot, version, checksum, data_json, updated_at | 完整存档 |
| LeaderboardItem | rank, user_id, nickname, value, stars, achieved_at | 榜单条目 |
| Level | id, level_key, name, type, difficulty, data_json, ai_generated, enabled, version, created_at, updated_at | 关卡 |
| Announcement | id, title, content, enabled, created_at | 公告 |
| PlayerEvent | event_type, payload_json, created_at | 事件埋点 |
| DashboardSummary | daily_active[], level_clear_rate[], difficulty_distribution[], play_time_distribution[], item_choice_distribution[], totals | 看板聚合 |
| AdminLog | id, admin_id, action, detail, created_at | 管理日志 |
| TokenPair | access_token, refresh_token, token_type, expires_in | 令牌对 |

## 11. WebSocket（可选加分）

- 端点：`/ws/announcements`（携带 token 查询参数认证）
- 用途：管理员发布 / 更新公告时实时推送给在线客户端；
- 消息格式：`{ "type": "announcement", "data": { "id": 1, "title": "...", "content": "..." } }`
- 断线自动重连，客户端以 REST 拉取兜底。
