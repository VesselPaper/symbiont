## 1. 总体架构设计

### 1.1 逻辑架构

```
┌──────────────────────── 客户端层（浏览器） ────────────────────────┐
│  Godot 4.7 WebGL 客户端                 Vue3 管理后台              │
│  表现层: 场景/UI/HUD                     表现层: 页面/看板(ECharts) │
│  逻辑层: Player/Combat/Map/Enemy/Level   逻辑层: stores/api         │
│  数据层: SaveManager/NetClient           数据层: axios 封装         │
└──────────────┬──────────────────────────────┬──────────────────────┘
               │ REST + JWT                   │ REST + JWT + RBAC
┌──────────────▼──────────────────────────────▼──────────────────────┐
│  服务层（FastAPI）                                                 │
│  api 路由层: auth/saves/leaderboard/stats/admin/ai/ws               │
│  service 业务层: AuthService/SaveService/LbService/StatsService/    │
│                AdminService/LevelGenService                         │
│  model 持久层: SQLAlchemy ORM (8 表)                                │
│  基础设施: Redis(缓存/限流/在线) · MySQL8(主存储)                    │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.2 物理部署架构（Docker Compose）

```
┌────────────────── 宿主机 ──────────────────┐
│  ┌─ client ─┐  ┌─ admin-web ─┐  ┌─ backend ─┐
│  │ nginx:80 │  │  nginx:80   │  │ uvicorn   │
│  │ WebGL    │  │  Vue3 dist  │  │ :8000     │
│  └────┬─────┘  └─────┬───────┘  └──┬────┬───┘
│       │ :8080        │ :8081        │    │
│  ┌────▼────┐  ┌──────▼─────────────▼┐   │
│  │  mysql  │  │        redis        │   │
│  └─────────┘  └─────────────────────┘   │
└──────────────────────────────────────────┘
```
- `client`：Nginx 托管 Godot WebGL 导出产物，端口 8080；配置 COOP/COEP 头适配 WebGL；
- `admin-web`：Nginx 托管 Vue3 构建产物，端口 8081；
- `backend`：FastAPI（uvicorn），端口 8000，依赖 mysql / redis；
- 客户端对后端 API 经同域 Nginx 反代 `/api` 访问（规避 CORS）。

### 2.1 工程结构（client/）

```
client/

├── scenes/

│   ├── player.tscn  enemy.tscn   # 角色 / 敌人
│   ├── ui/                       # 登录/主菜单/HUD/存档/排行/设置

├── autoload/
│   ├── game_manager.gd           # 全局状态（进度/能力/人性-异化值）
│   ├── save_manager.gd           # 本地存档 + 云同步
│   ├── net_client.gd             # API 封装（JWT/重试/批处理）

├── assets/  data/                # 素材 / 关卡 JSON
```

### 2.2 核心类设计（UML 摘要）

```
GameManager (autoload, 单例)
  - progress: GameProgress        # 当前进度
  - apply_ability(ability)  trigger_event(type, payload)

SaveManager (autoload, 单例)
  - save_local(slot)  load_local(slot)
  - upload(slot)  download(slot)  # 调 NetClient，处理 409 冲突

NetClient (autoload, 单例)
  - token: String
  - request(method, path, body) -> ApiResult
  - auto_refresh()  retry()

Player (CharacterBody2D)
  - velocity/gravity/jump/dash 参数（@export 可在编辑器调）
  - double_jump_enabled: bool    # 由 GameManager 能力控制
  - dash_enabled: bool
  - _physics_process()  _do_attack()  take_damage(n)

Enemy (CharacterBody2D 基类)
  - take_hit(dmg)  patrol()      # 子类: Patrol/Ranged/Flying/Elite

LevelLoader
  - parse_level(json)  build_room(room_data)  # JSON → 场景节点
  - player_start/doors/triggers

CombatSystem
  - damage_pipeline: attacker -> hitbox -> victim.take_hit
  - invincibility_frames  knockback
```

### 2.3 场景树（以 player.tscn 为例，已实现）

```
Player (CharacterBody2D) [+ player.gd]
├── CollisionShape2D (16×22)
├── Visual (Node2D)                # 米白色块 + 眼部，scale.x 控制朝向
├── AttackHitbox (Area2D)          # 面朝方向短程判定
│   └── CollisionShape2D (18×14)
└── Camera2D (zoom=3, 平滑跟随)
```

### 2.4 关键信号流

1. **攻击 → 命中**：`Player._do_attack()` 开启 AttackHitbox → `body_entered(body)` → `body.take_hit(dmg)` → Enemy 扣血/死亡 → `GameManager.trigger_event("kill", ...)`。
2. **能力解锁 → 探索**：玩家获得寄生物 → `GameManager.apply_ability("double_jump")` → 玩家二段跳启用 → 可进入新区域门禁。
3. **存档点 → 保存**：进入存档点区域 → `SaveManager.save_local(slot)` →（联网时）异步 `upload(slot)`。
4. **跑酷完成 → 上报**：`LevelResult` 结算（时间/星级）→ `NetClient` 调 `/leaderboard/submit` + `/stats/events`。

### 3.1 分层与模块

```

│   └── deps.py             # get_current_user / require_admin / 限流依赖
├── models/                 # SQLAlchemy ORM（对应 8 张表）

│   ├── admin/levels.py  players.py  dashboard.py  logs.py
│   └── ai.py  ws.py
├── services/
│   ├── auth_service.py     # 注册/登录/刷新/登出
│   ├── save_service.py     # 冲突检测/校验和
│   ├── lb_service.py       # Redis ZSET + MySQL 回源
│   ├── stats_service.py    # 事件落库 + 聚合查询
│   └── admin_service.py    # 关卡/玩家/公告 + 日志
└── ai/
    ├── levelgen.py         # LLM 调用 + schema 校验 + 重试
    └── hint.py             # 卡关渐进提示
```

### 3.2 JWT 认证流程

```
客户端                     FastAPI
  │  POST /auth/login      │ 校验凭据(bcrypt verify)
  │ ─────────────────────► │ 签发 access(60min)+refresh(7d)
  │ 存令牌                 │ refresh 存入 Redis(set, 可吊销)
  │                        │
  │  GET /saves            │ deps.get_current_user: 解析 Bearer → 校验 JWT → 载入用户
  │  Authorization: Bearer │ 40101 过期 → 客户端调 /auth/refresh
  │ ─────────────────────► │
  │ POST /auth/logout      │ 删除 Redis 中的 refresh → 吊销
```

### 3.3 云存档冲突策略（save_service）

- 上传时计算 `data_json` 的 SHA-256 → `checksum`；
- 冲突判定：请求 `version` + `data_json.timestamp` 均不晚于服务端 → 返回 `40901` + 服务端最新版；
- 客户端两选项：`X-Force-Overwrite: true`（覆盖，version+1）或保留远端（丢弃本地）；
- 防篡改：下载/上传均校验 checksum，不符拒绝并告警。

### 3.4 排行榜缓存策略（lb_service）

- 键：`lb:{metric_type}:{level_id or 'all'}`，Redis ZSET（score=value）；
- 上报最优成绩（`improved` 判定后）写 ZSET + 写库（异步）；
- 查询：ZREVRANGE / ZRANGE + ZRANK（个人名次）；未命中回源 MySQL 并重建缓存；
- 缓存失效：更新时同步写缓存，保证最终一致。

### 3.5 统计事件模型（stats_service）

- 事件类型白名单：`session / level_clear / death / ability_get / item_choice / parkour_result / login`；
- 批量上报（≤50 条/次）→ 写入 `player_events`（可异步队列）；
- 看板聚合：按日活跃（login/session 去重 user_id）、通过率（level_clear/尝试数）、难度分布、游玩时长分桶、道具抉择分布 → 供 `/admin/dashboard/summary`。

## 4. 数据库设计

### 4.1 ER 关系（文字版）

```
users 1 ─── 1 user_profiles
users 1 ─── N saves
users 1 ─── N leaderboard_entries ─── N ── 1 levels
users 1 ─── N player_events
users 1 ─── N admin_logs
users 1 ─── N announcements(created_by)
levels 1 ─── N leaderboard_entries
```

### 4.2 表结构（摘要，完整 DDL 见 `database/schema.sql`）

| 表 | 关键字段 | 索引 / 约束 |
|---|---|---|
| users | id, username, password_hash, nickname, role, status | uk_username |
| user_profiles | user_id, total_play_seconds, total_deaths, last_login_at | FK→users CASCADE |
| saves | user_id, slot, version, data_json(JSON), checksum, updated_at | uk(user_id,slot) |
| leaderboard_entries | user_id, metric_type, level_id, value, stars, achieved_at | uk(user,metric,level), idx(metric,value) |
| levels | level_key, name, type, difficulty, data_json(JSON), ai_generated, enabled, version | uk_level_key |
| announcements | title, content, enabled, created_by | FK→users SET NULL |
| player_events | user_id, event_type, payload_json(JSON), created_at | idx(user,time), idx(type,time) |
| admin_logs | admin_id, action, detail, created_at | idx(admin,time) |

字符集：utf8mb4 / utf8mb4_unicode_ci；外键约束 + 级联删除策略见 DDL。

## 5. 关键流程时序

### 5.1 云存档上传（含冲突）

```
SaveManager         NetClient        FastAPI:save_service        MySQL
     │ PUT /saves/1     │                 │                       │
     │ version=2        │                 │ 计算 checksum          │
     │─────────────────►│────────────────►│ 查 slot 现有 version    │
     │                  │                 │ version 冲突?           │
     │                  │                 │   ├─ 否 → 写库          │────►
     │                  │                 │   └─ 是 → 40901+最新版   │
     │◄────────────────│◄────────────────│                       │
     │ 409? → 弹窗选择覆盖/保留 │
     │ 覆盖: X-Force-Overwrite → 写库 version+1
```

### 5.2 跑酷成绩上报 → 排行 + 统计

```
客户端结算 → POST /leaderboard/submit {metric_type,level_id,value,stars}
  → lb_service: 优于旧值? → Redis ZSET 更新 + 异步写库
  → stats_service: player_events(type=parkour_result)
  → 返回 {improved, rank, best}
```

### 5.3 AI 关卡生成

```
管理后台 → POST /ai/levelgen {prompt,...}
  → levelgen: 调 LLM → 关卡 JSON
  → schema 校验（失败重试 ×2）
  → 成功返回 → 管理端预览 → 确认后 POST /admin/levels 入库
```

## 6. 安全设计

| 项 | 方案 |
|---|---|
| 密码 | bcrypt（cost=12）哈希，绝不存明文 |
| 认证 | JWT access + refresh；refresh 存 Redis 可吊销 |
| 授权 | RBAC：`require_admin` 依赖拦截管理接口 |
| 存档防篡改 | 服务端 SHA-256 校验和，不符拒绝 |
| 输入校验 | Pydantic v2 模型 + 关卡 JSON schema 校验 |
| 限流 | 登录 / 注册 / 事件上报接口基于 Redis 令牌桶限流 |
| 传输 | 生产环境 HTTPS（反代终止） |
| 内容安全 | 游戏内容安全化呈现（选题文档过审纪律） |

## 7. 异常与容错

| 场景 | 处理 |
|---|---|
| 数据库不可用 | 后端启动健康检查失败不启动；运行时 50000 错误码 + 日志告警 |
| Redis 不可用 | 排行榜回源 MySQL（降级慢但不失败）；限流降级为全放行 |
| 云存档网络失败 | 客户端本地存档兜底，后台重试队列 |
| AI 生成失败 | 重试 2 次后返回错误，保留上次合法版本 |
| WebGL 浏览器兼容 | 检测 WebGL2，不支持时给出降级提示 |
| 崩溃不丢档 | 存档点 + 本地即时写盘 + 云同步 |
