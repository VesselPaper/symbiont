# 03 系统详细设计

## 一、总体架构

| 层 | 内容 |
|---|---|
| 客户端 | Godot 4.7，纯 GDScript，2D |
| 数据管道 | SQL → SQLite → JSON，DataDB 运行时加载 |
| 后端 | FastAPI，分层：路由 → 服务 → 数据访问（SQLAlchemy） |
| 数据层 | MySQL 8（users / saves / events / leaderboard） |
| 部署 | docker-compose：mysql8 + server + nginx |

### 2.3 全局状态机

BOOT → MAIN_MENU → PLAYING → PAUSED → ENDING / GAME_OVER
状态由 GameManager 管理，切换时经 EventBus 广播。

### 2.4 关键机制

| 机制 | 做法 |
|---|---|
| 主菜单 | 启动进 `main.tscn`：开始新游戏 `start_new_game()` 后切教学关；继续读最近槽位，按 `current_floor` 回层；黑场 0.4s；`_leaving` 防重复点击 |
| HUD | 左下角五枚骨片读玩家 `hp`，献祭计数读 `GameManager.sacrifice_count`，拾取提示监听 `item_picked`；CanvasLayer 1，不压 Boss 血条/结局 |
| 暂停/存档 | Esc 暂停整棵树；槽位 1 保存 GameManager + 玩家位置/血量/持剑 + 背包 + 场景；读档先暂存玩家数据，同层原地恢复，跨层解除暂停后切场景 |
| 玩家移动 | 手感参数常量集中：跳高 3.7×身高、土狼时间、跳缓冲；蒸汽靴二段跳只加一次空中跳，不替代一段跳 |
| 攻击判定 | Area2D 判定框，命中 damageable 组目标；刀光三层（柔光/主刀光/白芯）+ 命中扩散环 + 短震屏，只做表现不改判定 |
| 命中反馈 | 横砍顿帧 0.035s、下劈 0.060s；下劈命中 6.8px/0.16s 震屏 + 玩家压扁 + 向上反弹。只冻结玩家物理，不改全局时间 |
| 互相击退 | 敌人按 `knockback_weight` 反比被推：史莱姆 1 / 孢子 2 / Boss 8；玩家反作用力随重量增加。敌人硬直 0.12～0.18s，玩家攻击后 0.16s 不响应移动，不能原地连按 J 推怪 |
| 铁剑跨层 | `GameManager.has_weapon` 保存持有状态；Player `_ready` 继承、拾取写回、复活补回，避免第三层/读档后空手 |
| 下劈跳高 | 每帧物理空间查询（PhysicsShapeQueryParameters2D），避免漏判 |
| 献祭流程 | 靠近祭坛按 K → 消耗肢体 → 全局计数 +1 → 肢体飞入石碗、触须收拢、紫黑屏闪 → 玩家背部长出寄生组织（外观随献祭次数增加）→ 0.55s 后播 `sacrifice_after_1/2` 低语 |
| 拒绝献祭 | 仅新手祭坛：有肢体且未献祭时按 R → `refuse_die` 台词 → 0.65s 黑场 → `ending_reached("refuse_die")`；不改献祭计数，按 K 回主菜单；没肢体按 R 只提示 |
| 结局结算 | 新手祭坛按 R 拒绝走 `refuse_die`（不进三层）。普通通关：Boss 死后走进出口门，读 `sacrifice_count`：==1 走 `human`，>1 走 `transformed`。真 HE：Boss 死后用入口旧货梯回起点，捡骨片，祭坛按 K 归还，写 `true_he_unlocked` 并直接结算 `true_he`；判定优先级 `true_he_unlocked` > `sacrifice_count`。结局名/说明从 `endings` 表读，黑场显示后按 K 重置回教学关/主菜单 |
| 关卡切换 | 教学关 0.5s 黑场 → 第一层；第一层门缝判定 + 0.5s 黑场 → 第二层；第二层门槛判定 + 0.5s 黑场 → 第三层；每层进场 0.55s 淡入。判定区会等层门对话念完再切，避免吞台词；演示按 F2 直接跳过教学。Boss 死后第三层货梯反向切回教学关，`true_he_return` 旗标让教学状态机停用、全部门打开、起点生成骨片 |
| 第二层阵营 | 工程师/祭司各有一套 offer→confirm→after 对话；第一次 K 听提议，提议播完才允许第二次 K 确认；选择写 `GameManager.faction` 和 `floor2_faction_*` 旗标，封印门下沉，玩家出现蒸汽靴/污化腿外观；已选后另一名 NPC 变暗且不能改阵营 |
| 第三层 Boss | 守门者 hp/attack 从 `enemies` 表读；远距离蓄力冲撞、近距离跳砸放两道贴地震波；半血进二阶段，动作间隔缩短；受击闪白，死亡发 `boss_defeated`、开出口门；Boss 被限制在厅内，不会被引下断口 |
| 教学物理门 | 平台缝里五扇骨栅栏：move/jump/attack/pogo 由 Tutorial 推进时打开，combat 要等战斗区敌人清空才开；不锁按键、不动物理手感 |
| 第一层机关 | 钟厅从左到右是断绳旁白 → 守钟人 → 吊钟 → 骨门墙（钟厅内的右墙），中间留出走路和听旁白的时间，钟厅这一整段不放怪；守钟人可反复对话；钟绳每帧按玩家实际坐标判定（左右各 170px / 上下 170px，和钟体视觉宽度对齐，站在钟左/中/右都能按 K，且不覆盖守钟人），K 走 `_input` 防被其他交互吃掉；对话统一走 `DialogueLocator`（AudioStreamPlayer 也有 `play/is_playing`，不能被当成旁白），提示统一走 `InteractionPrompt`，文案固定「K 拉钟绳」，旁白播放时整条提示隐藏、K 全给对话 → 锈钟摆动/钟声波纹/震屏/骨门下沉，`floor1_bell_rung` 旗标去重；骨门就是钟厅右边的墙，挡住钟厅到台阶的路 |
| 第一层剧情 | 入场延迟 0.6 秒 + 钟厅/祭坛/断桥/遗物廊/层门五个 Area2D 触发器，旗标去重，每段只播一次；只有祭坛另有可重复调查点（按 K 重播），层门路过看一次就够；空中碰到触发器会等落地再播，走路触发时水平速度立刻归零；对话期间敌人 process_mode 冻结，结束后恢复 |

## 三、数据设计

### 3.1 服务器 MySQL

| 表 | 说明 |
|---|---|
| users | 账号，username 唯一 |
| saves | 远程存档，user_id + slot 唯一，save_data JSON |
| events | 埋点，event + payload JSON |
| leaderboard | 排行榜，board + score |

### 3.2 游戏内容库（SQLite）

items / enemies / npc / dialogues / endings / sacrifices 六张表，字段见 schema.sql。

### 3.3 数据管道

改 SQL → build → export → DataDB → 运行时读取。

## 四、服务器设计

| 项 | 方案 |
|---|---|
| 分层 | 路由 → 服务 → ORM |
| 鉴权 | JWT（python-jose），密码 bcrypt 哈希 |
| 埋点 | 批量写入，事件 id 去重 |
| 排行榜 | SQL 排序，board 区分榜单 |

## 五、部署设计

docker-compose 三容器：mysql8 / server / nginx。nginx 反代 /api 到 server，托管 Web 版静态资源。首次启动自动建表。

## 八、变更记录
