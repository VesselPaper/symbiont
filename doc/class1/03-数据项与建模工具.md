# 03 数据项与建模工具

课程：软件工程 ｜ 组号：2 组 ｜ 项目：共生之缚 Symbiont

## 一、建模工具

传统工具 + AI 工具一起用，先画对再补漏，最后人工审校。

| 类别 | 工具 | 用途 |
|---|---|---|
| 传统 | Draw.io / StarUML / PlantUML | 类图、用例图、状态图、时序图 |
| 传统 | 白板 / 便利贴 / Excel | 需求研讨、功能划分、数据项登记 |
| AI | AI 画图（自然语言 → PlantUML/Mermaid） | 出图初稿，人工校核 |
| AI | AI 需求分析 / 代码助手 | 抽数据项、生成 SQL 与代码骨架 |

经验：AI 快但会编。图和清单要回到真实代码文件（schema.sql、models.py、存档代码）逐项核对。

## 二、三种核心图

| 图 | 回答的问题 | 本项目落点 |
|---|---|---|
| 用例图 | 谁（角色）能做什么 | 游客/账号/组员 × 游玩/教学/献祭/存档/排行榜（`uml/用例图.png`） |
| 类图 | 系统有哪些对象、属性、关联 | 后端四模型（`uml/后端类图.png`） |
| 状态转换图 | 对象有哪些状态、怎么切换 | 游戏全局状态机 + 教程状态机（`uml/游戏状态图.png`、`uml/教程状态图.png`） |

## 三、数据项清单

### 3.1 游戏内容（静态，SQL 管）

| 数据项 | 关键字段 | 对应需求 |
|---|---|---|
| items 物品 | id, name, type, stats, obtain, flags | F-05、F-12 |
| enemies 敌人 | id, name, hp, speed, behavior, attack_damage, drops | F-03、F-12 |
| npc NPC | id, name, faction, location | F-04、F-13 |
| dialogues 对话 | id, npc_id, lines(JSON), next_id, branch | F-04 |
| endings 结局 | id, name, condition, weight | F-11、F-14 |
| sacrifices 献祭改造 | id, part, route, effect(JSON) | F-12、F-13 |

### 3.2 存档数据（动态，Schema v1）

| 数据项 | 类型 | 说明 |
|---|---|---|
| version | int | 存档格式版本（当前 1） |
| saved_at | string | 保存时间 |
| game_progress.sacrifice_count | int | 献祭次数（结局依据） |
| game_progress.monster_limb_count | int | 肢体持有数 |
| game_progress.current_floor | string | 当前楼层 |
| game_progress.faction | string | 阵营（""/heretic/engineer） |
| game_progress.flags | dict | 剧情旗标 |
| player / inventory / levels | dict | M1/M2 定稿后填入 |

### 3.3 后端数据（MySQL）

| 表 | 关键字段 | 说明 |
|---|---|---|
| users | id, username 唯一, password_hash, created_at | 账号 |
| saves | id, user_id, slot, save_data(JSON), updated_at | 远程存档 |
| events | id, user_id 可空, event, payload(JSON), created_at | 埋点 |
| leaderboard | id, board, user_id, score, meta(JSON), created_at | 排行榜 |

## 四、数据一致性约定

1. 内容数据一处改 SQL，导出 JSON 给游戏读，运行时禁止手改；
2. 存档 Schema v1 同时约束本地档和远程档；
3. 数据项变了，先改 SQL/代码，再更新本文档和接口文档。
