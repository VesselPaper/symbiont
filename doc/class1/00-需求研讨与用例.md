# 00 需求研讨与用例

课程：软件工程 ｜ 组号：2 组 ｜ 项目：共生之缚 Symbiont

本文件含项目概述、用户角色、完整需求清单、非功能需求、验收标准。配套图：`uml/用例图.png`。

## 一、项目概述

一句话定位：无魔法、蒸汽时代的深渊地牢里，一名骑士在"献祭获得力量"与"守住人性"之间做选择。

| 项 | 内容 |
|---|---|
| 技术形态 | Godot 4.7 客户端（纯 GDScript）＋ FastAPI + MySQL ＋ docker 全栈 |
| 运行环境 | Windows 桌面 + 浏览器，单机为主、联网可选 |
| 玩法闭环 | 醒来 → 教学 → 猎杀怪物 → 拾取肢体 → 祭坛献祭 → 获得力量 → 爬出深渊 |

## 二、用户角色

| 角色 | 说明 | 主要需求 |
|---|---|---|
| 玩家（游客） | 不登录直接玩 | 玩通教学关，本地存档 |
| 玩家（账号） | 注册登录后 | 远程存档同步、统计上报 |
| 组员/维护者 | 管理数据、部署 | 改数据（SQL）、起服务（docker）、看后端探针 |

## 四、待拍板问题

| 问题 | 说明 |
|---|---|
| 存档槽位数 | 默认 3，是否可改 |
| 是否自动存档 | 手动/自动 |
| 双流派数值 | 钩锁 vs 大跳基线 |
| 三结局条件 | 献祭次数阈值；"拒绝即死"是否计入通关 |
| HE 道具 | 人线道具是否达成更好结局 |
| 三层地图 | 规模与回起点引导 |

以上不阻塞 M1 收尾，进 M2/M3 前由 2 组拍板。

## 五、用例图

![共生之缚系统用例图](uml/用例图.png)

- 参与者：玩家（游客/账号）、组员。
- 客户端用例：开始游戏与教学、移动/跳跃/攻击/下劈、拾取肢体与祭坛献祭、本地存档/读档。

## 六、非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 60FPS，GL Compatibility，资源占用低 |
| 可玩性 | 无致命 bug，教学关 5 分钟内通关，手感参数可调 |
| 兼容性 | Windows + 浏览器，Godot 4.7 统一 |
| 网络 | 单机优先，离线入队、联网上报 |
| 数据 | 内容数据由 SQL 导出，存档 Schema v1 |
| 安全 | 密码哈希、token 鉴权 |
| 质量 | CI 三 job 全绿、PR review、main 保护 |

## 七、验收标准

1. 三层地牢、双流派、三结局、存档可用、无致命 bug；
2. 后端 FastAPI + MySQL，OpenAPI、pytest 全绿、数据真实入库；
3. docker compose 一键拉起，浏览器可玩；
4. 课程文档、数据库脚本、周报齐备；
5. CI 绿、main 保护、README 完整。
