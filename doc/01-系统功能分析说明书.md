## 2. 系统概述

### 2.1 系统定位
面向课程演示与完整软件工程实践的**游戏 + 后台一体化系统**：
- **客户端**：Godot 4.7 WebGL 网页游戏（类银河恶魔城 + 跑酷），浏览器直接游玩；
- **后台**：FastAPI 服务提供账号、云存档、排行榜、数据统计、管理后台 API；
- **管理端**：Vue3 Web 管理后台，供管理员（教师 / 组员）配置关卡、管理玩家与公告、查看数据看板。

### 2.2 功能架构图

```
┌─────────────────────────────────────────────────────────────┐
│                         玩家浏览器                           │
│  ┌─────────────────────┐         ┌───────────────────────┐  │
│  │ Godot WebGL 客户端    │         │ Vue3 管理后台          │  │
│  │ 移动/战斗/探索/跑酷    │         │ 关卡配置/玩家/公告/看板  │  │
│  │ 存档/排行/登录 UI     │         │                       │  │
│  └─────────┬───────────┘         └───────────┬───────────┘  │
└────────────┼─────────────────────────────────┼──────────────┘
             │ RESTful API (JWT)               │ RESTful API (JWT + RBAC)
┌────────────▼─────────────────────────────────▼──────────────┐
│ FastAPI 后端                                                │
│ Auth │ Save │ Leaderboard │ Stats │ Admin │ AI(可选)         │
└────────────┬─────────────────────────────────┬──────────────┘
      MySQL 8（业务数据）            Redis 7（榜单缓存/限流/会话）
```

## 4. 功能需求

> 编号规则：FR-C-xx 客户端功能；FR-B-xx 后台功能。每条含优先级（P0 必须 / P1 重要 / P2 可选）。

### 4.1 客户端功能

#### FR-C-01 角色控制（P0）
1. 输入：A/D 或 ←/→ 移动，空格 / W / ↑ 跳跃，Shift / K 冲刺，J / X 攻击；
2. 移动手感：地面加速度 / 空中操控 / 摩擦力；跳跃含**土狼时间**与**输入缓冲**；下落加速、松键跳变矮；
3. 二段跳（能力成长解锁后）；冲刺（短时高速 + 冷却）；
4. 受击反馈：击退、无敌帧、屏幕震动（轻量）。

#### FR-C-02 战斗系统（P0）
1. 攻击：短程判定框（面朝方向）、攻击冷却；
2. 敌人受击：受击接口（HP / 击退 / 死亡）；
3. 生命 / 能量系统：血瓶与能量恢复道具；
4. 死亡重生：从最近存档点重生，死亡次数计入统计与排行。

#### FR-C-03 能力门控探索（P0）
1. 3 个能力：二段跳、冲刺、破墙，来源为寄生物共生事件；
2. 地图房间连通：新能力解锁新区域（单向门 / 门锁 / 机关）；
3. 地图显示：房间结构 + 探索迷雾（未探索区域纯黑，免迷雾系统）；
4. 传送点、存档点、隐藏区域与少量收集物。

#### FR-C-04 敌人与 Boss（P0）
1. 4 种基础敌人：巡逻型、远程型、飞行型、精英型（差异化行为 AI）；
2. 2 场 Boss：心核守卫、深渊之母（阶段式行为，阶段切换动画/数值变化）。

#### FR-C-05 跑酷挑战关（P0）
1. 3 个独立跑酷关：时限冲刺、连续跳跃 / 冲刺、躲避陷阱；
2. 计时 + 最佳成绩 + 1-3 星评级；通关解锁下一关；
3. 成绩上报后端（排行 + 统计）。

#### FR-C-06 关卡与地图数据（P0）
1. 关卡 JSON 数据驱动（房间 / 平台 / 敌人 / 机关 / 出生点），引擎按数据渲染；
2. 关卡数据来源：内置关卡 / 管理后台配置 / AI 生成（可选）；
3. 单一地牢主题：土 + 石墙 tile 复用（≤8 块），高亮交互物。

#### FR-C-07 存档与进度（P0）
1. 3 个本地存档位 + 自动存档点 + 死亡重生；
2. 持久化：已收集能力、道具、人性/异化值、地图探索度、跑酷成绩；
3. 云存档：登录后上传 / 下载同步（见 FR-B-02）。

#### FR-C-08 双路线成长（P0）
1. 共生道具使用方式三选一（食用 / 供奉 / 灌注）改变"人性值 ↔ 异化值"；
2. 3 个关键道具分叉节点；按数值解锁能力分支（人路线 / 异化路线）；
3. 两条路线共享约 80% 内容；外观轻量变化（纹路 / 微光粒子）；
4. 结局：2 主线结局 + 1 隐藏结局（可选）。

#### FR-C-09 客户端 UI（P0）
1. 登录 / 注册界面、主菜单、HUD（生命 / 能量 / 人性-异化值）、存档界面、排行榜界面、设置界面；
2. 新手引导：首房间教学提示（移动 / 跳跃 / 攻击）。

#### FR-C-10 网络与后台对接（P0）
1. JWT 登录态管理（access 自动续期）；API 客户端封装；
2. 云存档上传 / 下载、排行榜拉取、公告拉取、事件埋点上报（批量、失败重试）。

### 4.2 后台功能

#### FR-B-01 账号与认证（P0）
1. 玩家注册 / 登录 / 登出；管理员登录；
2. JWT：access token（60 分钟）+ refresh token（7 天）；刷新接口；
3. 密码 bcrypt 哈希存储；账号状态（active / banned）校验。

#### FR-B-02 云存档（P0）
1. 存档列表、按槽位上传播档、下载存档；
2. 冲突检测：版本号 + 时间戳；客户端可选择覆盖或保留远端；
3. 防篡改：服务端计算并校验 SHA-256 校验和。

#### FR-B-03 排行榜（P0）
1. 三维度：通关时间（clear_time，越小越好）、死亡数（deaths，越小越好）、完成度（completion，越大越好）；
2. 总榜 + 关卡分榜（level_id）+ 跑酷星级榜（stars）；
3. 分页查询 + 个人名次查询；Redis 缓存热榜。

#### FR-B-04 数据统计（P0）
1. 事件埋点接收（session / level_clear / death / ability_get / item_choice / parkour_result 等）；
2. 管理看板数据：每日活跃、关卡通过率、难度分布、游玩时长分布、道具抉择分布；
3. 聚合查询接口供管理端图表（ECharts）使用。

#### FR-B-05 管理后台（P0）
1. 关卡配置：CRUD + 启停 + 版本管理（JSON 数据校验）；
2. 玩家管理：列表查询、封禁 / 解封；
3. 公告管理：CRUD + 启停（客户端登录拉取公告）；
4. 数据看板：≥3 类核心图表（活跃趋势 / 通过率排行 / 难度分布）；
5. 管理操作日志（admin_logs）。

#### FR-B-06 AI 辅助（P2 可选加分）
1. AI 关卡生成：输入主题 / 参数 → LLM 输出关卡布局 JSON → schema 校验（失败重试）→ 入库 → 客户端试玩；
2. AI 卡关提示：玩家卡关时渐进提示（提示 → 思路 → 步骤，可开关）。

### 5.2 关键用例详述

#### UC-01 注册登录
- 前置：无
- 主流程：
  1. 玩家打开客户端，进入登录界面；
  2. 选择注册：输入用户名 / 密码 / 昵称，提交；
  3. 系统校验唯一性、密码强度，bcrypt 哈希入库；
  4. 返回 JWT（access + refresh），进入主菜单；
  5. 已注册用户选择登录：校验凭据，签发新令牌。
- 异常流：用户名已存在 / 凭据错误 / 账号被禁用（提示对应错误码）。
- 后置：客户端持有 JWT，可访问受保护接口。

#### UC-06 存档 / 云存档
- 前置：玩家已登录
- 主流程：
  1. 游戏中自动存档点触发本地保存；
  2. 玩家在存档界面选择"上传云端"；
  3. 客户端将存档数据 + 版本号上传，服务端校验和校验后入库；
  4. 玩家选择"下载云端"：客户端拉取列表，选择槽位下载；
  5. 冲突时（服务端版本高于本地）：提示选择"覆盖远端"或"保留远端"。
- 异常流：校验和不符（拒绝并提示存档异常）；网络失败（本地存档兜底，下次重试）。

#### UC-07 查看排行榜
- 前置：玩家已登录（游客可选只读）
- 主流程：
  1. 客户端排行榜界面选择维度（通关时间 / 死亡数 / 完成度）；
  2. 选择范围：总榜 / 某关卡分榜 / 跑酷星级榜；
  3. 后端从 Redis 缓存 / MySQL 分页返回榜单 + 个人名次；
  4. 客户端渲染榜单（昵称 / 数值 / 星级）。
- 后置：玩家可看到自己的名次与差距。

#### UC-09 AI 生成关卡（可选）
- 前置：管理员登录管理后台
- 主流程：
  1. 管理员在"关卡配置"页点击"AI 生成"；
  2. 输入主题 / 难度 / 尺寸参数，提交；
  3. 后端调用 LLM 生成关卡布局 JSON，进行 schema 校验（失败自动重试 2 次）；
  4. 校验通过后入库（ai_generated=1），可在"试玩"中验证；
  5. 管理员人工微调 / 启用发布。
- 异常流：LLM 输出不合法（重试仍失败 → 返回错误并保留上次合法版本）。

## 6. 业务流程

### 6.1 登录 → 游戏 → 存档 → 云上传
```
玩家 → 客户端登录(UC-01) → 主菜单 → 新建/读档(UC-02)
     → 游玩(UC-03/04/05) → 自动存档点(本地)
     → 存档界面上传云端(UC-06) → 服务端校验入库
```

### 6.2 死亡 → 重生
```
玩家受击 HP=0 → 死亡动画 → 死亡事件上报(统计+死亡数)
     → 从最近存档点重生(扣除已用消耗品，进度保留)
```

### 6.3 跑酷挑战 → 成绩上报 → 排行
```
进入跑酷关(UC-05) → 计时开始 → 完成/失败
     → 星级评定(时间阈值) → 成绩上报后端
     → 更新排行榜(UC-07) + 事件埋点(统计)
```

### 6.4 道具抉择 → 双路线成长
```
获得共生道具 → 提示三选一(食用/供奉/灌注) → 人性/异化值变化
     → 数值达阈值解锁能力分支 → 外观轻量变化
     → 剧情节点推进 → 结局分支(UC-08)
```

## 10. 验收标准

1. 客户端可玩：移动 / 跳跃 / 二段跳 / 冲刺 / 攻击手感达标，能力门控闭环可通，1 场 Boss 可战；
2. 后台可用：注册登录、云存档同步、排行榜、统计埋点全链路打通；
3. 管理端可用：关卡配置 / 玩家管理 / 公告 / 数据看板可操作；
4. Docker Compose 一键部署，WebGL 网页可直接游玩；
5. 7 份交付文档齐全，内容与实现一致；
6. 内容安全合规（过审纪律）。
