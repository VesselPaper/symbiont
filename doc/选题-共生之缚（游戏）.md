# 《软件工程》课程设计 选题确认（游戏方向）· 丰富版

## 项目名称

**共生之缚：像素风横版动作探索游戏（类银河恶魔城 + 跑酷）+ 完整后台系统**

> 仓库名（英文）：`symbiont`
> 仓库地址：https://github.com/VesselPaper/symbiont

## 选题说明

老师提供的 10 个课程设计题目已被其他组选取；本组经组内讨论决定采用**自主选题 + 游戏方向**（老师允许游戏项目，并将提供技术栈）。

本组自主设计一款**类银河恶魔城（Metroidvania）横版动作游戏**，融合**跑酷挑战关卡**，并配套**完整后台系统**（账号、云存档、排行榜、数据统计、管理后台、AI 辅助），以《软件工程》全流程实践为标准，达到课程设计全栈系统的难度与复杂度要求。

### 世界观设定（共生之缚）

主角因"献祭"被投入深渊地牢「烬渊」，濒死之际被一种深渊寄生物共生，得以存活并获得异于常人的能力。玩家在探索中获得的道具，其**使用方式**将影响主角的成长方向——**偏向"人"（人性）或偏向"非人"（异化）**，不同方向解锁不同能力分支，最终走向不同的结局。

**安全化呈现**（过审纪律）：不血腥不恐怖；「献祭」淡化表述；寄生物设计为发光小精灵系；异化仅轻量外观变化（纹路 / 微光粒子）。

### 核心体验

- **能力门控探索**：能力源自寄生物共生（二段跳、冲刺、破墙），解锁之前无法到达的地图区域，形成"探索 → 获得能力 → 解锁新区域"的闭环；
- **双路线成长**：道具使用方式影响"人性值 ↔ 异化值"，解锁不同成长分支，叙事与机制统一；
- **跑酷关卡**：在探索主地图之外，提供独立跑酷挑战关（时限冲刺、连续跳跃、躲避陷阱）；
- **完整后台系统**：账号 / 云存档 / 排行榜 / 数据统计 / 管理后台 / AI 辅助，作为软件工程考核支撑；
- **单一地牢主题**：像素风，土 + 石墙素材体系复用，在有限工作量下保证完成度与手感。

美术方案采用**像素极简风**（色块角色 + 复用 tile），规避无专职美术的短板；开发以 3 名有能力的组员 + AI Agent 辅助推进。

## 一）、核心功能需求

### 客户端（游戏本体）

#### 1）玩家控制与战斗（核心体验）
- 角色移动、跳跃、冲刺、二段跳（能力成长）、攻击、受击
- 生命 / 能量系统、恢复道具、死亡重生机制
- 手感调校：帧级碰撞判定、输入缓冲（跳跃缓冲 / 土狼时间）、受击反馈（击退、无敌帧、屏幕震动）
- 支持键盘（WASD + 空格 + Shift + J）与手柄基础按键

#### 2）能力门控探索（核心机制）
- 3 个能力成长点：二段跳、冲刺、破墙（能力来源：寄生物共生）
- 新能力解锁新区域，形成探索闭环
- 地图显示（房间结构、探索迷雾）、传送点、存档点
- 隐藏区域与收集物（少量）

#### 3）敌人与战斗
- 4 种基础敌人：巡逻型、远程型、飞行型、精英型
- 2 场 Boss 战（阶段式行为：心核守卫、深渊之母）
- AI 行为：巡逻、追击、攻击模式切换、阶段切换

#### 4）跑酷挑战关卡（特色）
- 3 个独立跑酷关：时限冲刺、连续跳跃 / 冲刺、躲避陷阱
- 计时与最佳成绩、星星评级（1-3 星）、通关解锁

#### 5）关卡与地图系统
- 单一地牢主题「烬渊」：土 + 石墙 tile 复用，像素风
- 地图：3 层主区域 + 中央枢纽 + 心核 Boss 区，主地牢约 20 个房间
- 房间布局、单向门 / 门锁、机关与隐藏区域
- 关卡数据可配置：JSON 关卡格式（引擎渲染）+ 管理后台可编辑 + AI 生成

#### 6）存档与游戏进度
- 3 个存档位、自动存档点、死亡后从存档点重生
- 已收集能力、道具、地图探索度持久化
- 云存档同步（跨设备续玩，见后台系统）

#### 7）道具与成长（双路线核心）
- 少量可收集道具：血瓶、能量、共生道具
- **双路线成长**：共生道具的**使用方式**（食用 / 供奉 / 灌注）影响"人性值 ↔ 异化值"
- 3 个关键共生道具形成分叉节点；两条路线**共享约 80% 内容**，避免工作量翻倍
- 按数值解锁能力分支：人路线（稳健战斗）与异化路线（强化共生能力）
- 能力升级路径（服务能力门控 + 双路线），外观轻量变化（纹路 / 微光粒子）
- 结局：2 个主线结局（人性 / 异化）+ 1 个隐藏结局（可选加分）

#### 8）客户端 UI
- 登录 / 注册界面、主菜单、HUD（生命/能量/人性-异化值）、存档界面、排行榜界面、设置界面
- 新手引导（首房间教学提示）

### 后台系统（软件工程考核点，必须做）

#### 9）账号与权限
- 学生玩家 / 管理员两类角色注册登录（JWT）
- 管理员 RBAC：仅管理员可访问管理后台接口

#### 10）云存档同步
- 多存档位上传 / 下载、版本号 + 时间戳冲突检测、SHA-256 校验和防篡改

#### 11）排行榜
- 三维度：通关时间、死亡数、完成度
- 总榜 + 关卡分榜 + 跑酷星级榜；分页、个人名次查询

#### 12）数据统计（管理看板数据源）
- 玩家行为事件埋点：游玩时长、死亡次数、能力获取、道具抉择、关卡通过率、难度分布
- 每日活跃统计

#### 13）管理后台
- 关卡配置管理（JSON 数据 CRUD、启停、版本）
- 玩家管理（查看 / 封禁）、公告管理（CRUD、启停）
- 数据看板（ECharts 图表 ≥3 类）、管理操作日志

#### 14）AI 辅助功能（可选加分项，保留大模型能力）
- AI 生成关卡：大模型输出关卡布局 JSON（schema 校验后入库，引擎渲染试玩）
- AI 解谜提示：玩家卡关时提供渐进提示（提示 → 思路 → 步骤）

## 二）、技术要求

> 技术栈以老师提供为准，本部分为自主选定方案；若老师指定引擎，仅客户端模块调整。

| 层 | 技术 | 说明 |
|---|---|---|
| 客户端 | **Godot 4.7（GDScript）** | 场景文本化、对 Agent 友好、可导出 WebGL；2D 像素能力内置 |
| 后端 | Python 3.13 + FastAPI + SQLAlchemy 2 + Alembic | 账号 / 云存档 / 排行榜 / 统计 / 管理 |
| 数据库 | MySQL 8 + Redis 7 | 业务数据 + 缓存 / 榜单 / 限流 |
| 管理后台 | Vue3 + Vite + Element Plus + ECharts | PC Web 管理端 + 数据看板 |
| 认证 | JWT（access + refresh）+ RBAC | player / admin 双角色 |
| 部署 | Docker Compose（客户端 WebGL + 管理端 + 后端 + 数据库） | 一键部署，网页直接可玩 |
| AI（可选） | 大模型 API（DeepSeek 等）生成关卡 / 提示 | 可开关、可切换模型 |
| 版本管理 | Git + GitHub（公开仓库 symbiont） | 全程版本管理 |

### 非功能需求（初步）
- 性能：目标 60 FPS；API P95 < 200ms；场景加载 / 存档读写低延迟
- 可用性：操作手感优先；新手引导；崩溃不丢档（存档点 + 云存档）
- 安全：JWT 鉴权、存档 SHA-256 防篡改、RBAC、接口限流
- 可维护性：客户端逻辑模块化（角色 / 地图 / 敌人 / 关卡数据分离）、后端分层（router/service/model）、配置化
- 可扩展性：新关卡 / 新能力 / 新敌人可通过配置与模块扩展
- 部署：Docker 一键部署、网页版可直接游玩演示

## 四）、与已有题目的差异化

| 相近题目 | 差异点 |
|---|---|
| 题目 9：AI 试衣镜、题目 1：师范 AI 试讲台 等 | 本组为**游戏方向自主选题**，以玩法（能力门控探索 + 跑酷）为核心体验，配套完整后台系统支撑软件工程流程考核 |

## 五）、美术与视觉规范（地牢极简方案）

> 原则：地图之外大大方方用黑色，地图之内大大方方用土与石墙——极简素材体系支撑完整探索氛围。

| 元素 | 方案 |
|---|---|
| 地图外 / 未探索区 | 纯黑（#000000），未探索区域天然为黑色，无需额外迷雾系统 |
| 地图内 | 土 + 石墙 tile 体系（≤8 块基础 tile 复用 + 少量裂缝 / 苔藓装饰） |
| 角色与敌人 | 高亮色轮廓（米白 / 暖黄），与黑色背景和土墙拉开对比，保证可读性 |
| 交互物（门 / 机关 / 陷阱） | 高亮红 / 橙色标识，一眼可辨 |
| 光效点缀 | 少量程序化粒子（火炬余烬、萤火），营造地牢氛围 |
| 跑酷关 | 复用同一套土墙体系 + 黑色虚空，仅增加计时 / 评级 UI |
| 技术要点 | 探索过的区域才加载渲染土墙 tile；摄像机跟随（3x 缩放），未探索区域留黑 |
