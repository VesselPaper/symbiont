# 04 系统安装部署文档

## 一、环境要求

| 项 | 要求 |
|---|---|
| Docker | Docker Desktop（Windows）/ docker compose v2 |
| 桌面版运行 | Godot 4.7.2（编辑器直接运行） |
| 浏览器 | 现代浏览器（Web 版） |
| openssl | 生成自签证书（Git for Windows 自带） |

## 二、部署架构

Web 版不是"nginx 托管静态文件 + 后端各开一个端口"，中间那一层是**应用代理**：

```
浏览器
  │  80 → 308 跳转
  ▼
代理 proxy（443，TLS 终止 / 限流 / 静态托管 / 安全响应头）
  ├── /            静态页与 Godot 导出包
  ├── /status.html 网关状态页
  └── /api/ ──► upstream 地址池（least_conn + 故障摘除）
                     ├── server-1 :8000（仅内网）
                     ├── server-2 :8000（仅内网）
                     └── server-3 :8000（仅内网）
                                │
                                └──► mysql :3306（仅内网）
```

对外只开放 80 和 443。后端与数据库都不映射宿主机端口，源站在容器网络里，
外部即使知道 8000 / 3306 也连不上——这是代理"藏住源站"的直接效果。

## 三、一键部署（docker）

```powershell
scripts/gen_cert.ps1                                  # 首次部署生成自签证书
docker compose -f deploy/docker-compose.yml up -d --build
```

| 服务 | 地址 | 说明 |
|---|---|---|
| proxy | https://localhost | 入口网关（自签证书，浏览器需点"继续访问"） |
| proxy | https://localhost/status.html | 状态页：看每次请求落到哪台后端 |
| server-1/2/3 | 内网 :8000 | 三台无状态后端，外部不可达 |
| mysql | 内网 :3306 | MySQL 8，首次启动自动执行 schema.sql + seed.sql |

端口说明：宿主机 8080 常被其他程序占用，因此网关直接使用 80/443。
本机若已占用这两个端口，改 `docker-compose.yml` 的 `ports` 即可。

## 四、镜像构建

| 镜像 | Dockerfile | 说明 |
|---|---|---|
| proxy | deploy/Dockerfile.proxy | nginx:alpine + 网关配置 + 落地页/状态页 |
| server | deploy/Dockerfile.server | FastAPI + uvicorn :8000 |

构建顺序：先导出 Godot Web 版（`scripts/export_web.ps1`）再构建 proxy。
导出产物不进镜像，由 compose 的注释掉的挂载挂进 `/game`；
没有导出时网关仍提供落地页与状态页，代理与负载均衡功能不受影响。

## 六、验证与对照

```powershell
python deploy/bench.py --mode seq --n 12     # 分流是否均匀
python deploy/bench.py --n 40 --concurrency 40   # 限流是否生效（应出现 429）
```

无网关的对照态（仅用于演示，不要用于部署）：

```powershell
docker compose -f deploy/docker-compose.baseline.yml up -d --build
curl -i http://localhost:18081/api/v1/health
```

对照结论：

| 项 | 无网关 | 有网关 |
|---|---|---|
| 后端端口 | 18081 对宿主机开放 | 仅内网 |
| 传输 | 明文 HTTP | TLS |
| 版本指纹 | `server: uvicorn` | `server: nginx`（版本已抹） |
| 后端数量 | 1 | 3，挂一台自动绕开 |
| 限流 | 无 | 8 r/s + burst 20，超出 429 |

## 七、故障排查

| 问题 | 处理 |
|---|---|
| 浏览器提示证书不安全 | 自签证书的正常提示，点"继续访问" |
| 网关起不来，日志报证书读取失败 | 先跑 `scripts/gen_cert.ps1` |
| 80/443 被占用 | 改 `docker-compose.yml` 的 `ports` 映射 |
| 后端起不来 | `docker compose logs server-1` |
| `/api` 全部 429 | 限流阈值，调整 `nginx.conf` 的 `rate` / `burst` |
| 两台编排互相顶替 | 两个文件都写了 `name:`，不要删 |
| 无网环境 | 单机可玩，网络层自动离线 |

## 九、变更记录

| 阶段 | 变更 |
|---|---|
| M0–M3 | MySQL + 后端 + game-web 三容器；game-web 只做静态托管与 `/api` 单后端反代 |
| M4-30 | Web 入口升级为网关：`upstream` 三副本（`least_conn` / `max_fails` / `keepalive` / `zone`）、TLS 终止与 80 跳转、`limit_req` + `limit_conn`（429）、请求体上限与分层超时、`server_tokens off`、安全响应头、`expires` 分级缓存、`X-Upstream` 回显；后端与数据库不再映射宿主机端口（原 8000 / 3306 的直连关闭）；`Dockerfile.game-web` 改名 `Dockerfile.proxy`；新增 `docker-compose.baseline.yml`（无网关对照）、`scripts/gen_cert.ps1`、`deploy/html/status.html`、`deploy/bench.py`、`deploy/tap.py`；两份编排加显式 `name:` 避免同目录项目名冲突 |
